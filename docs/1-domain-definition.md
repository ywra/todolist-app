## 2. 문제 정의

| # | 문제 | 해결 방향 |
|---|------|-----------|
| 1 | 기존 할일 관리 앱은 개인 전용 데이터 관리가 어렵다 | 사용자 인증을 통해 개인별 데이터를 격리하여 관리 |
| 2 | 할일의 종료일을 지정하는 기능이 부재하다 | 모든 할일에 시작일·종료일을 필수 속성으로 지정 |
| 3 | 인증 없이 접근 가능하여 개인 데이터 보호가 어렵다 | 회원 가입 및 로그인 후에만 할일 기능 접근 허용 |

## 3. 도메인 용어 정의

| 용어 | 설명 |
|------|------|
| 사용자 (User) | 회원 가입 후 로그인하여 서비스를 이용하는 개인 |
| 할일 (Todo) | 사용자가 등록한 개별 작업 단위 |
| 시작일 (Start Date) | 할일을 시작하기로 계획한 날짜 |
| 종료일 (Due Date) | 할일을 완료해야 하는 마감 날짜 |
| 완료 여부 (Completed) | 사용자가 할일을 성공적으로 마쳤음을 표시하는 상태 값 |
| 할일 상태 (Todo Status) | 시작일·종료일·완료 여부를 기반으로 산출되는 할일의 현재 상태 |

## 4. 핵심 도메인 모델

### 4.1 User (사용자)

| 속성 | 타입 | 필수 | 설명 |
|------|------|------|------|
| id | UUID | Y | 사용자 고유 식별자 |
| email | String | Y | 로그인 이메일 (고유값) |
| password | String | Y | 암호화된 비밀번호 |
| name | String | Y | 사용자 이름 |
| created_at | DateTime | Y | 계정 생성 일시 |

### 4.2 Todo (할일)

| 속성 | 타입 | 필수 | 설명 |
|------|------|------|------|
| id | UUID | Y | 할일 고유 식별자 |
| user_id | UUID | Y | 소유 사용자 식별자 (외래키) |
| title | String | Y | 할일 제목 |
| description | String | N | 할일 상세 설명 |
| start_date | Date | Y | 할일 시작일 |
| due_date | Date | Y | 할일 종료일 (마감일) |
| is_completed | Boolean | Y | 완료 여부 (기본값: false) |
| created_at | DateTime | Y | 할일 생성 일시 |
| updated_at | DateTime | Y | 할일 최종 수정 일시 |

## 5. 할일 상태 정의

할일 상태는 `start_date`, `due_date`, `is_completed`, 현재 날짜(Today)를 기반으로 산출됩니다.

| 상태 | 식별 조건 | 설명 |
|------|-----------|------|
| 시작전 (Pending) | `is_completed = false` AND `today < start_date` | 아직 시작일이 되지 않은 할일 |
| 진행중 (In Progress) | `is_completed = false` AND `start_date <= today <= due_date` | 시작일이 지났고 종료일 이내인 할일 |
| 완료 실패 (Overdue) | `is_completed = false` AND `today > due_date` | 종료일이 지났지만 완료되지 않은 할일 |
| 성공 완료 (Completed) | `is_completed = true` | 사용자가 완료 처리한 할일 |

## 6. 주요 기능 (유스케이스)

| UC# | 유스케이스 | 액터 | 설명 |
|-----|-----------|------|------|
| UC-01 | 회원 가입 | 비인증 사용자 | 이메일·비밀번호·이름으로 계정 생성 |
| UC-02 | 로그인 | 비인증 사용자 | 이메일·비밀번호 인증 후 JWT Access Token 발급 |
| UC-03 | 로그아웃 | 인증 사용자 | 클라이언트 토큰 삭제 |
| UC-04 | 할일 등록 | 인증 사용자 | 제목·시작일·종료일을 포함한 할일 생성 |
| UC-05 | 할일 목록 조회 | 인증 사용자 | 본인의 할일 목록을 상태 필터 및 정렬 기준으로 조회 |
| UC-06 | 할일 상세 조회 | 인증 사용자 | 특정 할일의 상세 정보 조회 |
| UC-07 | 할일 수정 | 인증 사용자 | 제목·설명·시작일·종료일 등 할일 정보 수정 |
| UC-08 | 할일 완료 처리 | 인증 사용자 | 완료 여부(is_completed)를 true로 업데이트 |
| UC-09 | 할일 삭제 | 인증 사용자 | 본인 소유의 할일 삭제 |
| UC-10 | 할일 완료 취소 | 인증 사용자 | 완료 처리된 할일을 미완료(is_completed = false) 상태로 되돌림 |

## 7. 비즈니스 규칙

| BR# | 규칙 | 관련 UC |
|-----|------|---------|
| BR-01 | 할일 기능은 로그인한 사용자만 접근할 수 있다. | UC-02, UC-03 |
| BR-02 | 사용자는 본인이 등록한 할일만 조회·수정·삭제할 수 있다. | UC-04 ~ UC-10 |
| BR-03 | 모든 할일에는 시작일과 종료일이 반드시 지정되어야 한다. | UC-04, UC-07 |
| BR-04 | 종료일은 시작일과 같거나 이후 날짜여야 한다. | UC-04, UC-07 |
| BR-05 | 할일 목록은 상태(시작전·진행중·완료 실패·성공 완료)로 필터링할 수 있다. | UC-05 |
| BR-06 | 할일 목록은 시작일 또는 종료일을 기준으로 오름차순·내림차순 정렬할 수 있다. | UC-05 |
| BR-07 | 완료 처리된 할일은 다시 미완료 상태로 되돌릴 수 있다. | UC-10 |
| BR-08 | 이메일은 사용자 계정의 고유 식별 수단이며, 중복 가입을 허용하지 않는다. | UC-01 |
| BR-09 | "종료된 할일" 필터는 완료 실패(Overdue)와 성공 완료(Completed)를 모두 포함한다. | UC-05 |
