### SCN-01. 회원 가입

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-01 |
| 시나리오 이름 | 회원 가입 |
| 관련 UC | UC-01 |
| 관련 BR | BR-08 |
| 액터 | 비인증 사용자 |

**사전 조건**
- 사용자가 서비스에 가입된 계정을 보유하지 않은 상태이다.
- 사용자가 회원 가입 페이지에 접근한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 이름, 이메일 주소, 비밀번호를 입력하고 가입 버튼을 클릭한다. | - |
| 2 | - | 입력값 유효성을 검증한다. (이름: 1~50자, 공백만 불가 / 이메일: RFC 5322 형식, 최대 255자 / 비밀번호: 8자 이상, 영문·숫자·특수문자 각 1자 이상 포함) |
| 3 | - | 입력한 이메일이 이미 가입된 계정인지 중복 여부를 확인한다. |
| 4 | - | 비밀번호를 bcrypt로 단방향 해시 암호화하여 저장한다. (평문 저장 금지) |
| 5 | - | 사용자 계정을 생성하고 로그인 페이지로 이동시킨다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-01-1 | 이름이 공백만으로 구성되거나 50자를 초과하는 경우 | 이름 필드에 유효성 오류 메시지를 표시하고 가입을 중단한다. |
| EX-01-2 | 이메일 형식이 RFC 5322를 준수하지 않거나 255자를 초과하는 경우 | 이메일 필드에 형식 오류 메시지를 표시하고 가입을 중단한다. |
| EX-01-3 | 비밀번호가 8자 미만이거나 영문·숫자·특수문자 중 하나 이상이 누락된 경우 | 비밀번호 필드에 정책 위반 메시지를 표시하고 가입을 중단한다. |
| EX-01-4 | 이미 가입된 이메일을 입력한 경우 (BR-08) | "이미 사용 중인 이메일입니다" 오류 메시지를 표시하고 가입을 중단한다. |

**사후 조건**
- 사용자 계정이 DB에 정상 저장된다.
- 비밀번호는 bcrypt 해시값으로 저장되며 평문은 저장되지 않는다.
- 사용자는 로그인 페이지로 이동하여 가입한 계정으로 로그인할 수 있다.

### SCN-02. 로그인

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-02 |
| 시나리오 이름 | 로그인 |
| 관련 UC | UC-02 |
| 관련 BR | BR-01 |
| 액터 | 비인증 사용자 |

**사전 조건**
- 사용자가 서비스에 가입된 계정을 보유하고 있다.
- 사용자가 로그인 페이지에 접근한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 이메일과 비밀번호를 입력하고 로그인 버튼을 클릭한다. | - |
| 2 | - | 입력한 이메일로 등록된 계정을 조회한다. |
| 3 | - | 입력한 비밀번호와 저장된 해시값을 bcrypt로 비교·검증한다. |
| 4 | - | 검증 성공 시 JWT Access Token(유효기간 1시간)을 발급한다. |
| 5 | - | 클라이언트에 토큰을 전달하고 할일 목록 페이지로 이동시킨다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-02-1 | 존재하지 않는 이메일을 입력한 경우 | "이메일 또는 비밀번호가 올바르지 않습니다" 메시지를 표시한다. (계정 존재 여부 노출 금지) |
| EX-02-2 | 비밀번호가 일치하지 않는 경우 | "이메일 또는 비밀번호가 올바르지 않습니다" 메시지를 표시한다. |

**사후 조건**
- 클라이언트는 JWT Access Token을 보관한다.
- 이후 할일 관련 모든 API 요청 시 Authorization 헤더에 `Bearer {token}` 형식으로 토큰을 포함시킨다.
- 사용자는 할일 목록 페이지에 접근할 수 있다.

| 시나리오 ID | SCN-03 |
| 시나리오 이름 | 로그아웃 |

| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 로그아웃 버튼을 클릭한다. | - |
| 2 | - | 클라이언트에서 저장된 JWT Access Token을 삭제한다. |
| 3 | - | 사용자를 로그인 페이지로 이동시킨다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-03-1 | 이미 토큰이 만료된 상태에서 로그아웃을 시도하는 경우 | 클라이언트에 저장된 토큰을 삭제하고 로그인 페이지로 이동시킨다. |

**사후 조건**
- 클라이언트에서 JWT Access Token이 삭제된다.
- 이후 할일 목록 페이지 등 인증이 필요한 페이지에 접근하면 로그인 페이지로 리다이렉트된다.

### SCN-04. 할일 등록

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-04 |
| 시나리오 이름 | 할일 등록 |
| 관련 UC | UC-04 |
| 관련 BR | BR-01, BR-02, BR-03, BR-04 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 사용자가 할일 등록 페이지 또는 등록 폼에 접근한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 제목(필수), 설명(선택), 시작일(필수), 종료일(필수)을 입력하고 등록 버튼을 클릭한다. | - |
| 2 | - | Authorization 헤더의 JWT 토큰을 검증한다. |
| 3 | - | 입력값 유효성을 검증한다. (제목: 1~200자, 공백만 불가 / 설명: 최대 2,000자 / 날짜: ISO 8601 형식 YYYY-MM-DD) |
| 4 | - | 종료일이 시작일과 같거나 이후인지 확인한다. (BR-04) |
| 5 | - | 할일을 DB에 저장한다. (user_id는 JWT에서 추출, is_completed 기본값 false) |
| 6 | - | 등록된 할일 정보를 반환하고 할일 목록 페이지로 이동시킨다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-04-1 | 로그인하지 않은 상태에서 등록 API를 호출한 경우 (BR-01) | 401 Unauthorized를 반환하고 로그인 페이지로 이동시킨다. |
| EX-04-2 | 제목이 공백만으로 구성되거나 200자를 초과하는 경우 | 제목 필드에 유효성 오류 메시지를 표시하고 등록을 중단한다. |
| EX-04-3 | 설명이 2,000자를 초과하는 경우 | 설명 필드에 길이 초과 오류 메시지를 표시하고 등록을 중단한다. |
| EX-04-4 | 시작일 또는 종료일이 입력되지 않았거나 날짜 형식이 올바르지 않은 경우 (BR-03) | 해당 날짜 필드에 오류 메시지를 표시하고 등록을 중단한다. |
| EX-04-5 | 종료일이 시작일보다 이전 날짜인 경우 (BR-04) | "종료일은 시작일 이후여야 합니다" 메시지를 표시하고 등록을 중단한다. |

**사후 조건**
- 새로운 할일이 DB에 저장된다. (is_completed = false)
- 할일의 초기 상태는 시작일·종료일·오늘 날짜 기준으로 자동 산출된다. (시작전/진행중/완료 실패 중 하나)
- 할일 목록에 새로 등록된 할일이 표시된다.

### SCN-05. 할일 목록 조회 (필터·정렬)

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-05 |
| 시나리오 이름 | 할일 목록 조회 |
| 관련 UC | UC-05 |
| 관련 BR | BR-01, BR-02, BR-05, BR-06, BR-09 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 사용자가 할일 목록 페이지에 접근한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 할일 목록 페이지에 접근한다. | - |
| 2 | - | Authorization 헤더의 JWT 토큰을 검증하고 user_id를 추출한다. |
| 3 | - | 해당 사용자의 할일만 조회한다. (BR-02) |
| 4 | - | 각 할일의 상태(시작전/진행중/완료 실패/성공 완료)를 start_date, due_date, is_completed, 오늘 날짜 기준으로 산출한다. |
| 5 | - | 기본 페이지 크기(20건)로 첫 페이지를 반환한다. 응답에 현재 페이지 번호, 페이지 크기, 전체 건수, 전체 페이지 수를 포함한다. |
| 6 | 상태 필터를 선택한다. (시작전 / 진행중 / 완료 실패 / 성공 완료 / 종료된 할일) | - |
| 7 | - | 선택한 상태에 해당하는 할일만 필터링한다. "종료된 할일" 선택 시 완료 실패(Overdue)와 성공 완료(Completed)를 모두 포함한다. (BR-05, BR-09) |
| 8 | 정렬 기준(시작일 또는 종료일)과 정렬 방향(오름차순 또는 내림차순)을 선택한다. | - |
| 9 | - | 선택한 기준으로 정렬하여 목록을 재반환한다. (BR-06) |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-05-1 | 로그인하지 않은 상태에서 목록 조회 API를 호출한 경우 (BR-01) | 401 Unauthorized를 반환하고 로그인 페이지로 이동시킨다. |
| EX-05-2 | 등록된 할일이 없는 경우 | 빈 목록과 전체 건수 0을 반환한다. |
| EX-05-3 | 요청한 페이지 크기가 100건을 초과하는 경우 | 최대 페이지 크기인 100건으로 제한하여 반환한다. |

**사후 조건**
- 사용자는 본인의 할일만 조회한다. 다른 사용자의 할일은 표시되지 않는다.
- 선택한 필터·정렬 조건이 반영된 목록이 화면에 표시된다.
- 페이지네이션 정보(현재 페이지, 전체 건수, 전체 페이지 수)가 제공된다.

### SCN-06. 할일 상세 조회

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-06 |
| 시나리오 이름 | 할일 상세 조회 |
| 관련 UC | UC-06 |
| 관련 BR | BR-01, BR-02 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 조회할 할일이 DB에 존재한다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 할일 목록에서 특정 할일 항목을 클릭한다. | - |
| 2 | - | Authorization 헤더의 JWT 토큰을 검증하고 user_id를 추출한다. |
| 3 | - | 요청한 할일 ID로 DB를 조회한다. |
| 4 | - | 해당 할일의 user_id가 요청자의 user_id와 일치하는지 확인한다. (BR-02) |
| 5 | - | 제목, 설명, 시작일, 종료일, 완료 여부, 현재 상태, 생성 일시, 수정 일시를 반환한다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-06-1 | 로그인하지 않은 상태에서 상세 조회 API를 호출한 경우 (BR-01) | 401 Unauthorized를 반환하고 로그인 페이지로 이동시킨다. |
| EX-06-2 | 존재하지 않는 할일 ID를 요청한 경우 | 404 Not Found를 반환한다. |
| EX-06-3 | 다른 사용자 소유의 할일을 요청한 경우 (BR-02) | 403 Forbidden을 반환한다. |

**사후 조건**
- 사용자는 본인 소유의 할일 상세 정보를 확인한다.
- 현재 날짜 기준으로 산출된 상태(시작전/진행중/완료 실패/성공 완료)가 함께 표시된다.

### SCN-07. 할일 수정

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-07 |
| 시나리오 이름 | 할일 수정 |

|------|------|
| 시나리오 ID | SCN-14 |
| 시나리오 이름 | 오늘의 할일 완료/취소 |
| 관련 UC | UC-14 |
| 관련 BR | BR-01, BR-02, BR-14 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 오늘의 할일이 DB에 존재하며 사용자 본인 소유이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 오늘의 할일 목록에서 할일 항목의 체크박스를 클릭한다. (완료 토글) | - |
| 2 | - | Authorization 헤더의 JWT 토큰을 검증한다. |
| 3 | - | 요청한 할일의 user_id가 요청자와 일치하는지 확인한다. |
| 4 | - | is_completed 값을 토글(true ↔ false)하여 업데이트한다. |
| 5 | - | 완료 시(is_completed = true) 보상 카운트를 증가시킨다. (BR-14) |
| 6 | - | 업데이트된 할일 정보를 반환하고 화면을 갱신한다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-14-1 | 로그인하지 않은 상태에서 완료 처리 API를 호출한 경우 (BR-01) | 401 Unauthorized를 반환한다. |
| EX-14-2 | 다른 사용자 소유의 오늘의 할일을 완료 처리하려는 경우 | 403 Forbidden을 반환한다. |
| EX-14-3 | 존재하지 않는 할일 ID를 요청한 경우 | 404 Not Found를 반환한다. |

**사후 조건**
- 해당 할일의 is_completed가 토글되어 저장된다.
- 완료 시 보상 카운트가 증가한다. (10/30/100 마일스톤 자동 달성)
- 오늘의 할일 목록에서 체크박스 상태가 즉시 반영된다.

### SCN-15. 오늘의 할일 달력 조회

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-15 |
| 시나리오 이름 | 오늘의 할일 달력 조회 |
| 관련 UC | UC-15 |
| 관련 BR | BR-01, BR-15 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 사용자가 오늘의 할일 페이지(/daily)의 달력 뷰에 접근한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 달력 뷰를 전환한다. | - |
| 2 | - | Authorization 헤더의 JWT 토큰을 검증한다. |
| 3 | - | 해당 월의 모든 오늘의 할일을 조회한다. (BR-15) |
| 4 | - | 각 날짜별로 완료/미완료 마커를 표시한다. (완료: 🟢, 미완료: 🔴) |
| 5 | 달력의 특정 날짜를 클릭한다. | - |
| 6 | - | 해당 날짜의 오늘의 할일 목록을 표시한다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-15-1 | 로그인하지 않은 상태에서 달력 데이터 API를 호출한 경우 (BR-01) | 401 Unauthorized를 반환하고 로그인 페이지로 이동시킨다. |
| EX-15-2 | 해당 날짜에 등록된 오늘의 할일이 없는 경우 | 빈 목록을 표시한다. |

**사후 조건**
- 달력에는 각 날짜별 오늘의 할일 완료 상태가 시각적으로 표시된다.
- 날짜 클릭 시 해당 날짜의 상세 할일 목록이 표시된다.

### SCN-16. 보상 설정

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-16 |
| 시나리오 이름 | 보상 설정 |
| 관련 UC | UC-16 |
| 관련 BR | BR-01, BR-16 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 사용자가 보상 페이지(/rewards)에 접근한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 보상 현황 페이지에서 "보상 설정" 버튼을 클릭한다. | - |
| 2 | - | 보상 설정 모달을 표시한다. (10/30/100 마일스톤 선택) |
| 3 | 마일스톤을 선택하고, 보상 제목과 상세 내용을 입력하고 저장 버튼을 클릭한다. | - |
| 4 | - | Authorization 헤더의 JWT 토큰을 검증한다. |
| 5 | - | 입력값 유효성을 검증한다. (제목: 1~200자, 공백만 불가 / 내용: 최대 2,000자) |
| 6 | - | 해당 마일스톤의 보상이 이미 존재하는지 확인한다. (BR-16) |
| 7 | - | 보상을 rewards 테이블에 저장(또는 업데이트)한다. |
| 8 | - | 보상 페이지를 갱신하고 성공 메시지를 표시한다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-16-1 | 로그인하지 않은 상태에서 보상 설정 API를 호출한 경우 (BR-01) | 401 Unauthorized를 반환한다. |
| EX-16-2 | 제목이 공백만으로 구성되거나 200자를 초과하는 경우 | 제목 필드에 유효성 오류 메시지를 표시한다. |
| EX-16-3 | 해당 마일스톤의 보상이 이미 설정되어 있는 경우 (BR-16) | 기존 보상을 수정 모드로 표시하고, 사용자가 선택할 수 있게 한다. |

**사후 조건**
- 새로운 보상이 rewards 테이블에 저장된다.
- 보상 페이지의 해당 마일스톤에 보상 제목이 표시된다.
- 사용자당 마일스톤별 1개의 보상만 존재한다. (UNIQUE 제약)

### SCN-17. 보상 달성

| 항목 | 내용 |
|------|------|
| 시나리오 ID | SCN-17 |
| 시나리오 이름 | 보상 달성 |
| 관련 UC | UC-17 |
| 관련 BR | BR-01, BR-17 |
| 액터 | 인증 사용자 |

**사전 조건**
- 사용자가 로그인 상태이며 유효한 JWT Access Token을 보유하고 있다.
- 사용자가 보상을 설정한 상태이다.
- 사용자가 오늘의 할일을 10개, 30개, 또는 100개 완료한 상태이다.

**정상 흐름**

| 단계 | 사용자 행동 | 시스템 처리 |
|------|------------|------------|
| 1 | 오늘의 할일을 완료한다. (10/30/100 마일스톤 도달) | - |
| 2 | - | 완료된 오늘의 할일을 기준으로 보상 카운트를 계산한다. (BR-17) |
| 3 | - | 특정 마일스톤(10/30/100)에 도달했는지 확인한다. |
| 4 | - | 마일스톤에 도달하면 해당 보상의 is_achieved를 true로 업데이트한다. |
| 5 | - | achieved_at 필드에 현재 일시를 기록한다. |
| 6 | 보상 페이지(/rewards)를 방문한다. | - |
| 7 | - | 달성한 보상이 골드 카드 배경과 함께 🏆 트로피 마크로 표시된다. |

**예외 흐름**

| 예외 ID | 조건 | 시스템 처리 |
|---------|------|------------|
| EX-17-1 | 보상이 설정되지 않은 상태에서 마일스톤에 도달한 경우 | 보상 설정을 유도하는 알림을 표시한다. |
| EX-17-2 | 이미 달성한 보상에 대해 다시 도달하려는 경우 | 해당 보상은 이미 달성 상태로 유지된다. |

**사후 조건**
- 달성한 보상의 is_achieved가 true로 저장된다.
- 달성 일시(achieved_at)가 DB에 기록된다.
- 보상 페이지에서 달성한 보상이 시각적으로 구분되어 표시된다. (골드 배경, 트로피 마크)
- 사용자는 달성한 보상의 상세 내용을 확인할 수 있다.

## 4. 공통 제약 사항 요약

### 4.1 인증 공통 규칙

- 할일 관련 모든 API(UC-04 ~ UC-10)는 유효한 JWT Access Token 없이 호출 시 401 Unauthorized를 반환한다.
- 다른 사용자 소유 할일에 접근 시 403 Forbidden을 반환한다.
- Access Token 유효기간은 1시간이며, 만료된 토큰으로 요청 시 401 Unauthorized를 반환한다.

### 4.2 할일 상태 산출 규칙

| 상태 | 산출 조건 |
|------|-----------|
| 시작전 (Pending) | is_completed = false AND 오늘 < start_date |
| 진행중 (In Progress) | is_completed = false AND start_date <= 오늘 <= due_date |
| 완료 실패 (Overdue) | is_completed = false AND 오늘 > due_date |
| 성공 완료 (Completed) | is_completed = true |

### 4.3 비밀번호 정책 요약

- 최소 8자 이상
- 영문(대소문자), 숫자, 특수문자(`!@#$%^&*()_+-=[]{}|;':",.<>?/`) 각 1자 이상 포함 필수
- bcrypt 단방향 해시 암호화 저장 (평문 저장 금지)

### 4.4 오늘의 할일 독립 원칙

- **오늘의 할일**은 **내 할일 목록(todos 테이블)**과 완전 독립된 별도 시스템이다. (daily_todos 테이블)
- 두 시스템의 데이터는 서로 영향을 주지 않는다.
- 오늘의 할일 완료 시 보상 카운트가 증가되지만, 내 할일 목록 완료는 보상과 무관하다.
- 사용자는 두 시스템을 동시에 사용할 수 있다.

### 4.5 보상 시스템 규칙

- **마일스톤**: 10, 30, 100 (오늘의 할일 완료 개수 기준)
- **자동 달성**: 오늘의 할일 완료 개수가 마일스톤에 도달하면 자동으로 보상이 달성된다. (수동 확인 불필요)
- **사용자당 마일스톤별 1개**: 각 마일스톤은 사용자당 최대 1개의 보상만 설정 가능 (UNIQUE 제약)
- **보상 상태**: 달성한 보상은 골드 카드 배경과 🏆 트로피 마크로 표시된다.
