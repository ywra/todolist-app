## 2. 배경 및 문제 정의

문제 정의 및 도메인 배경은 [도메인 정의서 §2 문제 정의](./1-domain-definition.md#2-문제-정의)를 참조한다.

핵심 요약:
- 개인 데이터 격리 미흡 → 사용자 인증 기반 데이터 분리로 해결
- 할일 마감 관리 기능 부재 → 시작일·종료일 필수 속성화로 해결
- 미인증 접근으로 인한 데이터 보안 취약 → 로그인 후에만 할일 기능 접근 허용

## 3. 목표 및 성공 지표

### 3.1 목표

- MVP 기능 (UC-01 ~ UC-10) 전체를 3일 이내 개발·배포 완료
- 사용자가 회원 가입부터 할일 CRUD까지 끊김 없이 수행 가능한 서비스 제공
- 모바일웹·데스크탑 웹 양쪽에서 동일한 사용 경험 보장

### 3.2 성공 지표

| 지표 | 기준 |
|------|------|
| MVP 기능 완성도 | UC-01 ~ UC-10 전 유스케이스 정상 동작 |
| 일정 준수 | 2026-04-03 이전 배포 완료 |
| 비기능 요구사항 충족 | 비밀번호 정책·데이터 제약·페이지네이션 정책 전체 적용 |
| 크로스 플랫폼 지원 | 모바일웹·데스크탑 웹 반응형 UI 정상 렌더링 |

## 4. 서비스 플랫폼 및 기술 스택

### 4.1 서비스 플랫폼

| 플랫폼 | 지원 여부 | 비고 |
|--------|----------|------|
| 데스크탑 웹 | 지원 | 반응형 UI 적용 |
| 모바일 웹 | 지원 | 반응형 UI 적용 |
| 네이티브 앱 (iOS/Android) | 미지원 | 향후 확장 고려 대상 |

### 4.2 기술 스택

3-tier 아키텍처(프론트엔드 - 백엔드 - 데이터베이스) 기반으로 구성한다.

| 레이어 | 기술 |
|--------|------|
| 프론트엔드 | React 19 + TypeScript + Zustand + TanStack Query |
| 백엔드 | Node.js + Express 5 + TypeScript + pg 라이브러리 |
| 데이터베이스 | PostgreSQL |
| 인증 | JWT (JSON Web Token) 기반 토큰 인증 |
| ORM/쿼리빌더 | 미사용 (pg 라이브러리로 Raw SQL 직접 작성) |
| 배포 환경 | 미정 |

> 도메인 정의서의 "세션/토큰" 혼용 표기는 본 PRD에서 JWT 토큰 방식으로 확정한다.

## 5. 기능 요구사항

유스케이스 목록 및 비즈니스 규칙 상세는 [도메인 정의서 §6 주요 기능](./1-domain-definition.md#6-주요-기능-유스케이스) 및 [§7 비즈니스 규칙](./1-domain-definition.md#7-비즈니스-규칙)을 참조한다.

### 5.1 MVP 범위 및 우선순위

전체 유스케이스(UC-01 ~ UC-10)를 1차 MVP에 모두 포함한다.

| UC# | 유스케이스 | MVP 포함 | 우선순위 |
|-----|-----------|----------|----------|
| UC-01 | 회원 가입 | Y | P1 |
| UC-02 | 로그인 | Y | P1 |
| UC-03 | 로그아웃 | Y | P1 |
| UC-04 | 할일 등록 | Y | P1 |
| UC-05 | 할일 목록 조회 (필터·정렬 포함) | Y | P1 |
| UC-06 | 할일 상세 조회 | Y | P2 |
| UC-07 | 할일 수정 | Y | P1 |
| UC-08 | 할일 완료 처리 | Y | P1 |
| UC-09 | 할일 삭제 | Y | P1 |
| UC-10 | 할일 완료 취소 | Y | P2 |

> 우선순위 기준: P1 = 핵심 흐름 필수, P2 = 품질·사용성 완성도

### 5.2 도메인 모델 참조

도메인 모델(User, Todo), 할일 상태 정의(Pending / In Progress / Overdue / Completed)는 [도메인 정의서 §4 핵심 도메인 모델](./1-domain-definition.md#4-핵심-도메인-모델) 및 [§5 할일 상태 정의](./1-domain-definition.md#5-할일-상태-정의)를 참조한다.

## 6. 비기능 요구사항

### 6.1 비밀번호 정책

| 항목 | 정책 |
|------|------|
| 최소 길이 | 8자 이상 |
| 구성 요소 | 영문(대소문자), 숫자, 특수문자를 각 1자 이상 포함 |
| 허용 특수문자 | `!@#$%^&*()_+-=[]{}|;':",.<>?/` |
| 저장 방식 | bcrypt 등 단방향 해시 암호화 후 저장 (평문 저장 금지) |

### 6.2 데이터 필드 제약

#### User

| 필드 | 제약 |
|------|------|
| email | 최대 255자, RFC 5322 이메일 형식 준수, 고유값(중복 불가) |
| password | 최소 8자, 영문+숫자+특수문자 조합 필수 |
| name | 최소 1자, 최대 50자, 공백만으로 구성 불가 |

#### Todo

| 필드 | 제약 |
|------|------|
| title | 최소 1자, 최대 200자, 공백만으로 구성 불가 |
| description | 최대 2,000자, 선택 입력 |
| start_date | ISO 8601 날짜 형식 (YYYY-MM-DD), 필수 |
| due_date | ISO 8601 날짜 형식 (YYYY-MM-DD), 필수, `start_date` 이상이어야 함 |

### 6.3 페이지네이션

| 항목 | 정책 |
|------|------|
| 방식 | Offset 기반 페이지네이션 |
| 기본 페이지 크기 | 20건 / 페이지 |
| 최대 페이지 크기 | 100건 / 페이지 |
| 응답 포함 정보 | 현재 페이지 번호, 페이지 크기, 전체 건수, 전체 페이지 수 |

### 6.4 인증 및 보안

| 항목 | 정책 |
|------|------|
| 인증 방식 | JWT (Access Token) |
| Access Token 만료 | 1시간 |
| 토큰 전달 방식 | HTTP Authorization 헤더 (`Bearer` 스킴) |
| 토큰 저장 위치 | 클라이언트 메모리 (Zustand Store). 새로고침 시 재로그인 필요 |
| 미인증 요청 처리 | 할일 관련 모든 API에서 401 Unauthorized 반환 |
| 타인 데이터 접근 | 403 Forbidden 반환 |
| HTTPS | 배포 환경 확정 시 필수 적용 |

### 6.5 응답성 및 호환성

| 항목 | 기준 |
|------|------|
| 반응형 UI | 모바일(360px 이상) ~ 데스크탑(1280px 이상) 전 구간 지원 |
| 브라우저 지원 | 최신 버전 Chrome, Safari, Edge, Firefox |
| API 응답 형식 | JSON |

## 7. 시스템 아키텍처 개요

### 7.1 3-Tier 구조

```
[클라이언트]
  React 19 + TypeScript
  Zustand (전역 상태 관리)
  TanStack Query (서버 상태·캐싱)
       |
       | HTTP/REST (JSON)
       |
[백엔드 서버]
  Node.js + Express
  JWT 인증 미들웨어
  pg 라이브러리 (Raw SQL)
       |
       | SQL
       |
[데이터베이스]
  PostgreSQL
  테이블: users, todos
```

### 7.2 주요 설계 원칙

- 백엔드는 RESTful API 서버로 동작하며 프론트엔드와 완전히 분리된다.
- ORM을 사용하지 않고 pg 라이브러리로 SQL을 직접 작성하여 쿼리 투명성을 확보한다.
- 인증은 Stateless JWT 방식으로 구현하며 서버 세션을 유지하지 않는다.
- 모든 할일 API는 JWT 검증 미들웨어를 통과한 후 처리된다.
